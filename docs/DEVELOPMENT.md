# JobAid（Interview Copilot）

一个跑在自己电脑上的面试辅助工具：**实时听清面试官的问题，用 WorkBuddy 内置大模型给出可以直接开口说的作答草稿，并把草稿显示在一个对屏幕共享不可见的悬浮窗里。**

---

## 界面风格

浅灰侧栏 + 居中首屏 + 底部输入卡，右上角黑色胶囊「开始监听」。
侧栏分「对话」「资源」两组，底部显示语音模型与防护状态；右侧是可折叠的设置栏（齿轮图标开关）。
首屏给三个快捷短语，第一次提问后自动收起，把位置让给作答内容。

底部输入卡可以手动提问（Enter 发送，Shift+Enter 换行），也可以粘贴面试官的问题让它重新作答。

## 界面结构

左侧四个入口，参考 WorkBuddy 的布局：

| 入口 | 作用 |
| --- | --- |
| **新建任务** | 实时作答。左侧作答建议 + 字幕，右侧音频来源 / 作答设置 / 屏幕防护 |
| **知识库** | 上传简历、指定项目资料库、编辑岗位 JD |
| **网络搜索** | 开关与检索条数；作答前先查网页，把摘要作为事实依据 |
| **技能** | 可编辑的作答取向（技术细节优先 / STAR / 反问卷…），启用的会追加到提示词 |
| **历史记录** | 每场面试自动存档，点开可看当时的问答 |

## 它能做什么

- **双路收音**：一路抓「系统声音」= 面试官在腾讯会议/飞书/Zoom 里说的话；一路抓「麦克风」= 你自己说的话。两路分开识别，AI 知道谁说了什么。
- **本地离线识别**：SenseVoice-Small 模型跑在本机 CPU 上，中文准确率高，约 15 倍实时速度，语音不出本机。
- **自动判断提问**：面试官说完一句话，命中提问特征就自动生成作答；一句话分两段说也能拼起来。
- **流式作答**：边生成边显示，通常 1～3 秒就能看到第一行。
- **悬浮窗防共享**：悬浮窗透明置顶、鼠标点击穿透、永不抢焦点，而且**不会被屏幕共享、录屏、截图捕获**（Windows `WDA_EXCLUDEFROMCAPTURE`）。控制台窗口同样受保护。
- **简历自动解析**：直接上传 PDF / Word 简历，自动抽成文字，不用手敲。
- **项目资料库**：指定一个文件夹（项目代码、设计文档、述职材料都行），提问时会自动检索最相关的片段塞给模型，所以它能答出你真实项目的细节，而不是编故事。
- **网络搜索**：开启后作答前会先检索网页（走必应，无需 API Key），把摘要作为事实依据，适合回答"什么是 XX"这类需要准确性的事实题。
- **技能**：预置了几种作答取向，也可以自己写一段指令，启用后会自动拼进提示词。

## 两种安装方式

**方式一：装成桌面应用（推荐）**

双击 `download/` 里的安装包，或在浏览器打开 `download/index.html` 点下载按钮。

```bash
download/AI-Assistant-Setup.exe   # 284 MB，含本地语音模型
```

装完桌面和开始菜单会有「JobAid」，双击即可，不需要 Node 环境。
安装包未做代码签名，首次运行 Windows 会弹 SmartScreen，点「更多信息 → 仍要运行」。

**方式二：源码运行**

```bash
cd interview-copilot
npm install          # 已装好可跳过
npm start
```

重新打包安装包：

```bash
npm run dist         # 产物在 build-out/
```

启动后：

1. 右侧「**我的资料**」里上传简历（PDF / Word），再「选择文件夹」指定项目资料库。
2. 点右上角 **开始监听**，允许麦克风和屏幕录制权限。
3. 让面试官说一句话，确认左侧「面试官」电平条在跳。
4. 点右侧「**一键隐藏所有窗口**」，确认按钮变成绿色并显示"已隐藏"。

> 首次启动会加载语音模型（约 2.5 秒），顶部状态变成绿色的「语音模型就绪」就可以用了。

### 关于「我的资料」

| 东西 | 说明 |
| --- | --- |
| 简历 | 支持 `.pdf` / `.docx` / `.doc` / `.txt` / `.md`。解析完可以点「编辑文字」手动修正，改动会立刻生效 |
| 项目资料库 | 选一个文件夹即可，会自动递归索引 `pdf/docx/doc/md/txt` 和常见代码文件（js/ts/py/java/go/sql…） |
| 索引规模 | 最多 600 个文件、单文件 2MB，自动跳过 `node_modules`、`.git`、`dist` 等目录 |
| 检索方式 | 本地 BM25，纯离线，不联网、不上传。问答时自动挑最相关的 4 段（约 2600 字）送进提示词 |
| 更新 | 改完文件点「重建索引」，只会重解析有变动的文件（实测无改动重建 6ms） |

作答卡片底部会显示「参考资料：xxx.md」，方便你判断这段回答是基于哪份材料。

> 扫描件 PDF（图片版）抽不出文字，会明确提示你换一份文字版。

## 工作原理

```
系统声音（回环）─┐
                 ├─→ 能量 VAD 自动断句 ─→ 重采样 16k ─→ SenseVoice 本地识别
麦克风 ──────────┘                                              │
                                                                ▼
                                              提问判定（问号/疑问词/请说说…）
                                                                │
                                        ┌───────────────────────┤
                                        │                       ▼
                          项目资料库 BM25 检索        简历 + JD 注入系统提示词
                          （挑最相关的 4 段）                    │
                                        └───────────┬───────────┘
                                                    ▼
                                    WorkBuddy 云服务 · DeepSeek 流式生成作答草稿
                                                    │
                                                    ▼
                                        透明置顶悬浮窗（对屏幕共享不可见）
```

### 关于「屏幕防护」

控制台右侧是**一个按钮**：点一下就把悬浮窗和控制台同时设为"对屏幕共享不可见"，并立刻自检告诉你结果。再点一下关闭。

底层是 Windows 10 2004+ 的 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，Electron 里对应 `win.setContentProtection(true)`。被标记的窗口不会出现在任何走系统捕获 API 的画面里：DXGI 桌面复制、Windows Graphics Capture、GDI 截图，以及基于它们的腾讯会议、飞书、Zoom、OBS、系统截图。

**自检怎么做的**（不关防护，全程安全，且不受背景动画干扰）：
藏起来连拍两张 → 得到"背景自己在动"造成的差异量（motion）；再显示出来拍一张 → 得到 delta。**净增量 = delta − motion** 才是悬浮窗带来的贡献。悬浮窗是不透明卡片，一旦被采到会盖掉大半个区域，净增量必然远超背景运动（实测 >70%），所以哪怕你背后在放视频也能给出确定结论。

三个结论：`净增 > 25%` = 被采集；`净增 < 8%` = 已隐藏；介于两者（背景突然剧变）会重试，仍不确定就如实报"这次没判断出来"，绝不会误报成"露了"。自检期间会暂停 4 秒一次的保护重贴，避免采样瞬间被干扰。

> ⚠️ **踩过的坑（很隐蔽）**
> 鼠标穿透 `win.setIgnoreMouseEvents()` 如果在**窗口显示之前**调用，会让显示亲和性失效，防护彻底作废——自检会报"仍可见，差异 95%"，但窗口看上去一切正常。
> 正确做法：**先 `setContentProtection`，等窗口 `show` 之后再设鼠标穿透**。`main.js` 里的 `armOverlay()` 就是干这个的，顺序别改。
> 另外，旧的"开保护截一张 / 关保护截一张"的自检方式本身有 500ms 的防护空窗，还会和 4 秒重贴循环打架，已废弃。

**悬浮窗隐身**
右侧「屏幕防护」里的开关控制悬浮窗是否显示在屏幕上（勾上=藏起来，再点「关闭隐藏」或按 `Ctrl+Shift+H` 恢复）。
控制台本身照常出现在任务栏，方便随时切回来。

**已知边界**：外接采集卡、远程桌面（向日葵/ToDesk/RDP）、手机拍屏这类链路不走系统捕获 API，保护不适用。遇到这种情况自检会如实报红，直接按 `Ctrl+Shift+H` 隐藏即可。

## 自检脚本

```bash
# 语音识别是否正常
node scripts/test-asr.js

# 端到端：音频流 → VAD 断句 → 识别（会外放一段测试语音）
env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe scripts/test-pipeline.js

# 系统声音回环 + 防共享是否真的生效
env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe scripts/test-probe.js

# 云端模型连通性
node scripts/test-chat.js

# 简历解析（PDF/DOCX）+ 资料库检索
env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe scripts/test-knowledge.js
```

`ELECTRON_RUN_AS_NODE=1` 的存在会让 Electron 退化成纯 Node、窗口起不来，所以 `npm start` 走的是 `launch.js`，它会先清掉这个变量。

## 听不到面试官？按这个顺序查

控制台右侧「音频来源」下面每个通道都有一行实时状态：`峰值 12 · 已识别 6 句`。开监听后先看这两个数字。

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 系统声音「峰值」一直是 0，12 秒后变红 | 回环设备没收到声音 | 见下 |
| 系统声音有峰值，但字幕不出来 | 音量太小 / VAD 阈值偏高 | 调大会议音量，或把 `audio-engine.js` 里阈值 `0.0055` 调小 |
| 字幕有了，但不出答案 | 没被判定成提问 | 按 `Ctrl+Shift+J` 手动生成；或往 `main.js` 的 `Q_WORDS` 里加词 |
| 两个通道都是 0 | 没点「开始监听」，或权限被拒 | 重新点一次，看是否弹权限提示 |

**系统声音峰值恒为 0 的常见原因**（按概率排序）：

1. **蓝牙耳机**。Windows 的 WASAPI 回环对蓝牙输出端经常拿不到流，表现为音轨存在但全是静音。→ 把默认播放设备换成 Realtek / USB 声卡再试。
2. 会议软件把声音输出到了**非默认设备**（比如指定了某个耳机）。→ 回环只跟系统默认播放设备走。
3. 会议里对方**根本没在出声**（静音、还没开始说话）。

想确认回环本身是否正常，可以跑：

```bash
env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe scripts/test-loopback-video.js
```

它会自己放一段测试音并报告 RMS；`RMS=0.09` 左右说明回环正常，`0` 说明这台机器的默认输出设备不给回环。

> 兜底方案：不用系统回环，改**外放 + 麦克风**收音（把「系统声音」关掉）。外放时麦克风能收到面试官的声音，代价是你自己的话也会被重复识别，且需要回声消除。

## 悬浮窗怎么移动、缩放、收起

- **按住标题栏拖动**，位置自动记住，下次启动还在原处
- **拖四边/四角缩放**（最小 300×96），调过大小后不再被内容高度自动覆盖
- **双击标题栏**＝最大化/还原（和普通窗口一致）
- 右上角 `– □ ×`：收起成一条标题栏 / 铺满屏幕 / 关闭（`Ctrl+Shift+H` 或托盘再唤出）
- 位置乱了：托盘右键 →「复位悬浮窗位置」

实现上没有用 `-webkit-app-region: drag`，因为这个悬浮窗是 `focusable:false`（永不抢焦点），
原生拖动依赖窗口激活，那套设置下不会响应。改成渲染层手动拖拽：按下时记录窗口左上角与指针位置，
移动时算**绝对坐标**发过去（不做逐帧累加，避免取整抖动），并用指针捕获保证甩出窗口外也不断。

悬浮窗默认是点击穿透的（不挡你操作会议软件），只有当指针移到标题栏那 38px 时才会短暂接收鼠标事件——所以既能拖，又不会挡住后面的窗口。

## 两个「隐藏」不是一回事

| 控件 | 藏的是什么 | 你自己屏幕上 |
| --- | --- | --- |
| 屏幕防护「隐藏窗口」 | 藏起来后，**屏幕共享/录屏/截图里看不到**这两个窗口 | 照常看得见 |
| 「悬浮窗隐身」开关 | 把悬浮窗**从你自己的屏幕上**收起来 | 看不见 |

点「隐藏窗口」按钮后如果发现窗口还在自己屏幕上，这是正常的——它挡的是采集，不是你的眼睛。

**开始监听会自动进入面试状态**：打开屏幕防护、收起控制台、确保悬浮窗可见。想关掉这个行为把配置里的 `autoGuardOnListen` 设为 `false`。

## 历史记录与「新建任务」

点左侧 **新建任务** 就是开下一场面试：上一场会自动存进「历史记录」，主界面清空、重新开始。

- 每答完一题就写盘（`%APPDATA%/interview-copilot/sessions.json`），异常退出也不丢
- 最多保留 40 场，只存在本机
- 历史记录里点开某一场，展开来看当时的问题和作答草稿

## 模拟面试官（用来试功能）

`模拟面试官.bat` 会用系统中文音色把题库念出来，声音走默认播放设备 → JobAid 经系统回环收到 → 走完整链路。这样你不用真人说话就能验证识别、判定、作答。

- 双击 `模拟面试官.bat`，空格朗读当前题，左右方向键切题，Esc 退出
- 命令行：`node scripts/interviewer.js --say 5` 只念第 5 题；`--all` 依次念完；`--list` 列题库
- 题库在 `scripts/questions.json`，按你的简历和 JD 写的 14 题，每题带 `hint`（面试官在听什么）

命令行启动 app 时加 `--autolisten` 可跳过点按钮直接开始监听。

> 注意：外放时麦克风会同时收到面试官的声音。程序会把这种"回声"识别出来并丢弃，不会污染上下文；但如果面试官那半句回环没收到，也会用回声补上。

## 使用建议

- **耳机比外放好**。外放时麦克风会串进面试官的声音，虽然有回声消除，但戴耳机两路分离最干净。
- **资料库别塞无关文件**。只放你真正会被问到的项目和材料，检索精度会明显更高。
- **先跑一次自检**。面试前 5 分钟：传简历 → 选资料库 → 开始监听 → 自检 → 让朋友说几句话看字幕对不对。
- **作答是草稿不是台词**。用它抓要点、补遗漏，别指望一字不差念出来。
- **别在禁用的场合用**。很多公司面试明确禁止第三方辅助工具，是否使用请先看清对方规则；考试、笔试、录屏留档类场景不要用。
